# CV adaptation rules (example for any person)

Copy this file to `cv_adaptation_instruction.md` in the same folder and edit it. Without that
file the app uses its built-in general rules. Words in double braces are filled in by the app:
`{{name}}`, `{{first_name}}`, `{{location}}`, `{{right_to_work}}`, `{{start}}`.

## 1. What may change

Only two parts of {{name}}'s master CV are rewritten for a job: the PROFILE paragraph and the
KEY SKILLS rows. The header, projects, work experience, education and languages stay exactly as
they are in the master CV. The result must still fit on one page.

## 2. What never changes

Dates, employers, job titles, degrees, project descriptions, contact details.

## 3. Honesty

Not in the master: add here, separated by commas, the technologies you want the app never to
claim for you, for example Kubernetes, Kafka, AWS. Anything that is not in the master CV is never
presented as experience.

## 4. How to adapt

- PROFILE: 3 to 5 sentences. Start from what the posting asks for most, and answer it with real
  evidence from the master CV. A technology that is not in the master CV may appear only as an
  interest ("keen to grow into ..."), never as experience.
- KEY SKILLS: reorder and regroup the rows so the skills the posting names come first. Use the
  posting's own words for a skill when the master CV has that skill under another name. Never add
  a skill that is not in the master CV.
- Keep the length of each part close to the master CV, so the page count does not change.
- Use an en dash with spaces, never an em dash. No emojis.

## 5. Example

Posting asks for: Python, REST APIs, Docker, CI/CD.
PROFILE starts with the Python and API work, names the real project where they were used, then
mentions Docker and the CI pipeline with one concrete fact each.
KEY SKILLS puts the "Backend" row first and moves unrelated rows to the end.
